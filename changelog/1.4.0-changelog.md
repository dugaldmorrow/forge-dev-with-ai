# Changelog: 1.4.0

**Date:** 25-May-2026, 23:28 AEST  
**Previous version:** 1.3.1  
**Change type:** MINOR

## Summary

Added two new slides to `Presentation.md` covering the discretionary nature of MCP server and agent skill invocation — a practically important and under-documented aspect of working with AI agents. The slides explain why agents may bypass configured tools and rely on training data instead, and provide four concrete techniques for enforcing tool use (explicit prompting, AGENTS.md standing rules, verification prompts, and skill-enforced invocation). Both slides are positioned immediately after the "MCP servers give agents live capabilities; skills give agents your team's static expertise" comparison slide.

## Changes

### Documentation

- **Presentation.md** — New slide added: "MCP and skill invocation is discretionary — the agent decides whether to use them". Explains the inference-time decision the agent makes between calling an MCP/skill versus answering from training data, with a code-block illustration of the decision branch and a consequences table for Forge-specific failures. Includes speaker notes with diagnostic techniques for Rovo Dev and Claude Code.
- **Presentation.md** — New slide added: "Enforce MCP and skill invocation with explicit prompts, AGENTS.md rules, and verification". Provides four practical enforcement techniques with concrete code examples: explicit prompting (with ❌/✅ comparison), AGENTS.md standing instruction block, verification prompt pattern, and skill-enforced invocation via SKILL.md. Includes speaker notes with honest caveats about the limits of each technique.
