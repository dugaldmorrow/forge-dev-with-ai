# Changelog: 1.9.0

**Date:** 27-May-2026, 16:33 AEST  
**Previous version:** 1.8.2  
**Change type:** MINOR

## Summary

Implemented recommendations from a systematic review of all slides against the presentation best practices guidelines (one idea per slide, 3–5 bullet maximum, Glance Test). Six changes were made across seven slides: one slide was split into two, two slides had excess content moved to speaker notes, two slides had bullet lists moved to speaker notes, one slide had its shopping list tightened, and one slide's title case inconsistency was corrected.

## Changes

### Presentation (Presentation.md)

- **"Add the Forge MCP Server in one config block — zero installation required"**: Split into two slides. The original slide combined the JSON config block with the config file locations table — two distinct ideas. Slide 1 now contains only the JSON block plus two concise callouts (the warning and the verification test). Slide 2 ("Add the config in the right place — locations vary by tool") contains the locations table and a Rovo Dev tip callout.
- **"Agent context files give every session a standing brief"**: Fixed title case inconsistency (was the only slide using title case; all other slides use sentence case). Removed the four "What to put in AGENTS.md" bullet points from the slide body — moved to speaker notes as a condensed inline list. The ETH Zurich statistic callout was retained as the sole supporting element alongside the hierarchy diagram. Also updated the label from "three-level" to "four-level" hierarchy to accurately reflect the diagram.
- **"Agents Read Your Codebase on Demand — They Don't Load It All at Once"**: Removed the "Scoping vs. loading" three-row table from the slide body. Moved the three distinctions (scoped to directory / context window / selective reading) to speaker notes as bullets, where they serve as a clarifying aside without competing with the flow diagram and best practices.
- **"`atlassian/forge-skills` is Atlassian's official skill bundle"**: Removed the commented-out Rovo Dev manual install steps from the code block on the slide. Moved the Rovo Dev caveat to speaker notes as a clearly labelled bullet point.
- **"A skill is just a SKILL.md file — version-controlled, portable, and team-shareable"**: Removed the four "Benefits of skills" bullet points from the slide body. Moved them to speaker notes as a condensed inline list. The two code blocks (directory structure and SKILL.md example) now stand unobstructed as the primary visual.
- **"The ideal Forge + AI setup combines an agent, two MCP servers, and a skill bundle"**: Removed the "Editor" section (two lines noting that any existing editor works). Collapsed the "Forge CLI" section from a header + sub-bullet into a single inline line. The Editor message was converted to a tip callout below the Forge CLI line.
- **"Rovo Dev is the only agent with full Atlassian context — Jira, Confluence, Bitbucket, and Forge"**: Corrected a factually inaccurate title. The original claim was misleading because any MCP-compatible agent can access Atlassian data by configuring the Atlassian MCP Server. The true differentiator is the Teamwork Graph, which is built-in and zero-config. New title: "Rovo Dev's Teamwork Graph gives it built-in Atlassian context no other agent has natively". Added a clarifying callout on the slide and an "Important nuance" section in speaker notes explaining the distinction between built-in access (Rovo Dev) and MCP-configured access (other agents).
