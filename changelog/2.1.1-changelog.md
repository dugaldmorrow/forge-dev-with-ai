**Date:** 2-Jun-2026, 14:19 AEST  
**Previous version:** 2.1.0

## Summary

Corrected an inaccurate and potentially misleading claim on slide 9 about Rovo Dev's Atlassian context capabilities. The original title implied exclusivity ("no other agent has natively") which is no longer accurate given the Atlassian MCP Server allows any agent to access Jira/Confluence data. The slide now accurately distinguishes between what the MCP server provides (Jira/Confluence access, available to any agent) and what the Teamwork Graph provides (richer relationship data — people, goals, teams — available only in Rovo Dev natively).

## Changes

### Presentation (Presentation.html)

- **Slide 9 (Rovo Dev differentiators) — title:** Changed from *"Rovo Dev / Rovo CLI's Teamwork Graph gives it built-in Atlassian context no other agent has natively"* to *"Rovo Dev's Teamwork Graph provides richer Atlassian context than the MCP server alone — and requires zero configuration"*
- **Slide 9 — Teamwork Graph bullet:** Expanded to clarify that the Teamwork Graph includes people, goals, and team relationships *not* exposed via the Atlassian MCP Server
- **Slide 9 — new clarifying bullet:** Added *"Any agent + Atlassian MCP gets Jira/Confluence access — only Rovo Dev gets the full Teamwork Graph out of the box"* to proactively address the obvious technical question

- **Slide 9 — blockquote removed:** The previous blockquote ("Other agents can connect to Atlassian data via the Atlassian MCP Server — but they require configuration") was partially inaccurate and replaced by the clarifying bullet on the slide itself
- **Slide 9 — speaker notes:** Updated to reflect the more nuanced distinction (depth and zero-config, not exclusivity of capability)
